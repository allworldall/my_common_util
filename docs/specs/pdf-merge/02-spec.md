# Spec：PDF 合并

## 目标

在工具集「文件处理」中新增「PDF合并」：用户上传两个 PDF，按页面上两个文件槽的展示顺序，把全部页依次拼成一个新 PDF 并下载。交互、保存方式、安全提示与现有「PDF拆分」对齐。处理在服务端完成，不长期存文件。

## 范围内

- 首页「文件处理」增加入口：PDF合并（排在 PDF拆分 与 PDF压缩 之间）
- 独立工具页：两个文件槽（先 / 后），各自上传、替换、展示文件名 / 页数 / 大小
- 合并顺序 = 页面上「先」槽全部页 + 「后」槽全部页（页码从 1 到末页，不改页内内容）
- 提供「交换顺序」，只交换两个槽的先后，不重新上传
- 合并成功后用与拆分相同的保存弹窗（选择位置保存 / 浏览器下载）
- 服务端接口：校验类型与魔数、按顺序复制页面、返回新 PDF
- FAQ：说明顺序、上限；用白话说明加密打不开、合并后面貌还在但「可填写表格 / 左侧目录 / 电子章」可能没了
- 部署：合并接口单独放宽 nginx 上传体积（两个文件合计可能超过现有 `/api/` 的 52MB）

## 范围外

- 一次合并 3 个及以上文件
- 按页码范围截取后再合并（先拆分再合并即可）
- 页面缩略图预览、在线翻页阅读
- 统一纸张尺寸、旋转、加水印、目录/书签合并
- 保留交互表单、附件、数字签名有效性
- 浏览器本地合并（不上传）
- 加密 PDF 的密码解锁

## 主流程

1. 用户打开 PDF合并页，看到上下两个文件槽，标注「第 1 个（在前）」和「第 2 个（在后）」
2. 用户向每个槽点击或拖入一个 PDF；前端校验扩展名/MIME 与单文件大小后，调用现有 `/api/pdf/info` 读取页数并展示
3. 两个槽都就绪后，「合并并下载」可点；用户可点「交换顺序」对调两个槽
4. 点击合并：按当前展示顺序把两个文件 POST 到 `/api/pdf/merge`
5. 服务端校验后按顺序复制全部页面，返回新 PDF
6. 前端弹出保存弹窗，用户保存或下载；默认文件名由后端给出

## 异常流程

- 当文件不是 PDF（扩展名/类型不对，或魔数不是 `%PDF-`）则提示「仅支持 PDF 文件」或「文件内容不是有效的 PDF」，不进入合并
- 当单文件超过大小上限则提示「文件大小不能超过{N}M」
- 当只选了其中一个文件就点合并则按钮保持禁用，或提示「请先选择两个 PDF」
- 当 PDF 加密、损坏、无法读页则提示明确失败原因（加密则「不支持加密的 PDF」）
- 当两个文件页数合计超过上限则拒绝并提示上限
- 当请求过于频繁则提示「请求过于频繁，请稍后再试」
- 当服务端/网关因体积或超时失败则提示可读错误，不留下临时文件

## 规则与约束

- 权限：与现有 `/api/pdf/**` 相同；配置了 `X-Api-Token` 则请求需带令牌
- 兼容：桌面与手机浏览器；保存位置选择仅在支持 File System Access 的安全上下文可用，其余走浏览器下载
- 性能：合并只做页面复制，不重渲染；单文件默认 50MB（与拆分一致）；两文件合计页数默认最多 200 页；同 IP 合并接口每分钟默认 10 次
- 安全：魔数校验；处理完立即返回，不长期存储；FAQ 提示勿上传高度敏感文件
- 页面尺寸：各页保持原尺寸，不统一
- 允许两个槽选同一个文件（用户可能想复制一份拼在后面）
- 下载文件名：`{文件1主名}+{文件2主名}.pdf`，非法字符替换为 `_`；完整文件名（含 `.pdf`）最长 180 个字符，超长时两个主名各截一半额度
- 上传字段按当前展示顺序命名：`file1`（在前）、`file2`（在后）
- 现有 `/api/` nginx 限制 52MB，两个 50MB 文件会在网关被拒，必须为 `/api/pdf/merge` 单独放到约 110MB（与压缩同级），Spring `max-request-size` 已是 110MB 可复用

## 验收标准

- [ ] 给定首页文件处理分类，当打开工具集，则能看到「PDF合并」入口，描述为将两个 PDF 按顺序合成一个
- [ ] 给定两个合法 PDF（A 共 2 页、B 共 3 页），当第 1 槽为 A、第 2 槽为 B 并合并，则结果为 5 页，顺序为 A1、A2、B1、B2、B3
- [ ] 给定同上两个文件，当用户先交换顺序再合并，则结果顺序为 B 的全部页再接 A 的全部页
- [ ] 给定两个槽都未齐，当查看合并按钮，则不可点
- [ ] 给定非 PDF 或伪装扩展名，当上传，则拒绝并提示，不调用合并
- [ ] 给定超过单文件大小上限的 PDF，当上传，则拒绝并提示上限
- [ ] 给定合计页数超过上限的两个 PDF，当合并，则拒绝并提示页数上限
- [ ] 给定加密 PDF，当读取信息或合并，则失败并提示不支持加密
- [ ] 给定合并成功，当弹出保存框，则可选「选择位置保存」或「浏览器下载」，得到可打开的 PDF
- [ ] 给定不同纸张尺寸的两个 PDF，当合并，则各页尺寸与原文件一致
- [ ] 给定处理完成，当检查服务端，则无长期保留的上传/结果文件

## 已确认决策

| 问题 | 结论 |
|---|---|
| 是否支持一次选 3 个及以上？ | 只支持正好 2 个 |
| 能否只合并各自的某几页？ | 否，整本合并；要截页先用拆分 |
| 两个槽能否对调？ | 提供「交换顺序」 |
| 要不要缩略图预览？ | 不要（大文件渲染缩略图会占浏览器内存） |
| 单文件大小 / 合计页数？ | 每个 50MB；合计最多 200 页 |
| 加密 / 表单 / 目录 / 电子章？ | 加密打不开就拒绝。合并只复印页面：看起来还是那些页，但可填写格子、左侧目录、电子章可能没了或失效，FAQ 写明 |
| 默认下载文件名？ | `{名1}+{名2}.pdf`，整名最长 180 字符，超长截主名 |
| 在哪处理？ | 服务端，与拆分/压缩一样 |
| nginx | `/api/pdf/merge` 单独 `client_max_body_size 110m` |
